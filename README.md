# 巫师牌 · 好友桌

中文 Wizard 好友网页游戏。3–6 人实时房间，邀请链接，机器人练习，自动跟色检查、胜墩判定和计分，逐轮成绩与手机布局。

**在线游玩：[Cloudflare 巫师牌](https://wizard-friends.wizard-friends.workers.dev/)**

所有成员请使用这个新地址。原 GitHub Pages 版本尚未切换到本中继，两边房间不互通。

## 巫师密室 · 3D 视觉版

Three.js / WebGL 实时渲染的木质牌桌、黄铜包边、烛台灯光、魔法阵、书册、水晶球与微粒。桌面卡牌有真实几何厚度、透视、投影、落牌过渡与胜墩高亮；手牌使用 HTML/CSS 的扇形排列和抬牌，保留键盘焦点与合法出牌限制。镜头和手牌角度不随鼠标移动。

主页采用全屏游戏主菜单：烛光牌桌作为背景，左侧显示标题、创建牌局、加入房间、单人练习、昵称与在线人数。正在进行的房间直接显示在右侧，手机上位于主菜单下方，可滚动查看并点击进入观战。房间码按需展开，邀请链接自动展开；页面底部提供规则和画质入口。没有宣传介绍、参数栏或底部营销说明。

等待大厅延续全屏牌桌场景，六个座位围桌排列；顶部保留房间码、人数、邀请和离开，底部提供机器人和「选择开局规则」。房主可移除玩家；人数不足或有人离线时显示简短原因并禁用投票。手机改为两列座位。

大厅及对局右上角的「聊天」打开可收起的房间聊天框，收起时提示未读消息；对局更新不会打断正在输入的草稿。消息由房主验证并同步，最多保留最近 100 条，每条 300 字符，每人 5 秒内最多发送 5 条；同房间刷新恢复和再来一局保留聊天，关闭房间后不永久归档。聊天仅显示文本，历史消息保留发送时的昵称。

新会话自动填入随机中文昵称及短尾码；同一标签页刷新、重连保留名字。房主统一检查所有座位，包括机器人和离线玩家，自动名称碰撞则重生成，手动重名则提示修改。大厅的「设置 → 改名」和对局「设置 → 改名」允许修改自己的昵称（1–16 字符），同步至座位、计分板及后续消息。

本轮翻开的主牌竖立于牌桌中央，约 16 秒转一周并轻微悬浮，带有实际牌面、原创背面和厚度。桌面圆纹与固定文字以蓝／红／绿／黄显示主牌花色；巫师待选色、小丑无主牌、牌库用尽及单色牌库分别说明。二维模式保留中央卡牌。主牌动画默认跟随系统减少动态效果偏好；「设置 → 主牌动画」可单独开关旋转与悬浮，并在本浏览器记住选择。

原创 BGM「烛光 · 预言」使用 Web Audio 合成柔和拨弦、钟音与和声，64 BPM、16 小节循环，无外部音频下载。第一次点击或键盘操作后低音量播放；主页、大厅和对局共用同一音频实例。「设置 → ♫ 音乐」可暂停和调音量，偏好保存在本机。切到后台自动暂停，返回后恢复；音乐仅在本机播放，不传输给其他玩家。

对局时牌桌铺满浏览器视口，手牌和当前操作浮在桌面下方。轮次显示在左上角，王牌显示在桌面；右上角「比分」展开排行榜，逐轮成绩与对局记录按需展开，「设置」提供规则、画质、音乐、改名、邀请与退出。终局自动展开成绩，随时可以关闭；Escape 可收起设置和比分面板。无需滚动整个页面，大量手牌在手牌区内滚动。

界面采用大按钮与高对比度文字：主页突出创建／加入房间，大厅的改名、离开、画质与音乐集中到「设置」，变体规则在每轮发牌前单独投票选择。局内常驻入口为聊天、比分和设置，牌桌只保留一处王牌标记；玩家信息直接显示「已赢 · 目标」，对局记录默认折叠。手牌增加清晰数字角标。

每位玩家每次出牌限时 30 秒（选王牌与预言阶段不计时），倒计时全员可见，最后 10 秒显示红色。时间到由房主自动代出合法牌，优先选择小丑或较小数字牌、最后才选巫师；仍遵守跟色限制。聊天、改名不延长时间；新出牌者重新计时，结算时停止。截止时间由房主保存并同步，访客不能触发超时操作；房主刷新可恢复原截止时间。房主浏览器被系统冻结时，代出会延后至恢复运行。

使用用户提供的 54 张 SVG 插画（冰霜、烈焰、森林、星辰各 13 张，以及巫师、小丑各一种），手牌、二维主牌和三维材质共用同一套图。四张巫师和四张小丑分别复用对应插画，完整牌库仍为 60 张；原有牌背保留。素材来源及字体许可见 [卡牌插画说明](src/assets/cards/README.md)。牌桌视觉参考 [Inscryption](https://store.steampowered.com/app/1092790/Inscryption/) 的烛光桌面与 [Liar's Bar](https://store.steampowered.com/app/3097560/Liars_Bar/) 的围桌空间感；未使用这两款游戏的模型、贴图、音频或角色素材。

数字牌每个点数有独立插画；巫师 W 和小丑 J 有各自人物图案。等待出牌或不是自己的回合时，手牌始终保留完整亮度和花色饱和度，可出牌的金边提示单独保留。手牌与三维牌面都叠加清晰的大号点数、花色提示；手机镜头拉近并按出牌数量放大卡牌，3–6 张均保留在屏幕内。牌面底部的微小英文仅作装饰。二维桌面与三维毛毡、木材稍微压暗并降低饱和度，让卡牌更突出。获胜牌使用明亮金边，获胜标记以浅金底、深色文字突出，二维和三维共用。

主页常驻「正在进行的房间」列表，开局、进度和观众人数自动更新，点击房间内的「进入观战」即可观看；没有对局时显示空态。只同步公开出牌、预估进度、轮次、计分、聊天和最近 100 条公开操作记录。观众不占玩家座位，不能出牌、投票、改名或发消息；任何规则下都看不到未出的手牌，秘密或尚未揭晓的预估与票面也不会下发。观众同标签页刷新后自动恢复，房主刷新后自动重连。单人练习不进入公开列表。

主页右下角或对局右上角的菜单内可切换「3D 质感 / 省电」。手机默认省电，通过关闭阴影与微粒、将场景更新限制在约 20 帧/秒降低开销；两种画质都保留抗锯齿和最高 2 倍设备像素渲染，避免点数模糊。页面隐藏或场景离开页面时停止绘制。尊重系统的减少动态效果偏好。不支持 WebGL 或图形上下文丢失时，自动显示二维牌桌，规则及联机功能保持可用。

`src/table-scene.js` 为三维场景，`src/card-art.js` 统一映射 `src/assets/cards/` 的牌面，`src/cinematic.css` 为视觉覆盖层。SVG 保持 320 × 480 的 2:3 比例，构建后以带哈希的独立文件按需加载，重复牌面共享 WebGL 纹理。模型、木纹及牌背由代码生成，无外部模型或运行时字体下载。

## 开始玩

1. 打开网站，使用随机昵称或自行修改，创建好友房间。
2. 复制邀请链接发给朋友。朋友打开链接，点击加入。
3. 至少三人即可选择规则；空位可添加机器人，最多六人。每位真人投票，结果确定后由房主发牌。
4. 每轮先预估赢墩数，再依次出牌。带金色高亮边框的手牌表示当前合法选择。
5. 房主在每墩结算后点击继续；每轮结算后点击「选择下一轮规则」，全体真人重新投票，房主确认后才发下一轮的牌。终局可再次开局。

标准局包含 20/15/12/10 轮（分别对应 3/4/5/6 人）。两种牌库均可选择 5 轮快速局。机器人仅为简单陪练策略，根据自己的可见信息操作。

## 每轮投票与变体

第一轮发牌前，真人分别选择牌库、预估方式、加减预估、先见之明与局长。**牌库与局长整局固定；预估方式、加减预估、先见之明每轮重新选择**，机器人不投票。提交前可以修改，提交后锁定；全部提交后逐项计票，最高票获选，平票项只在并列选项中重投，其他结果保留。

每轮投票中仅显示提交进度，席位冻结；离线等待重连。房主可以取消：开局投票回大厅调整，后续轮投票回上轮结算，分数和牌局进度保留。仅确认发牌时才进入下一轮并轮换庄家。再来一局保留成员、昵称、聊天，重新选择牌库、局长及首轮变体。

| 类别 | 行为 |
| --- | --- |
| 公开预估 | 按庄家左手顺序依次报数 |
| 隐藏预估 | 独立提交，全部提交后同时公开，再开始出牌 |
| 秘密数字 | 独立提交，只能看到自己的预估，本轮所有手牌打完后才全部公开 |
| 加减预估 | 仅配公开预估，最后一人不能让总预估等于本轮墩数；可同时开启先见之明 |
| 先见之明 | 开启的当轮选色／预估期间隐藏自己的整手牌、展示其他人的牌，全部预估后恢复正常 |
| 单色牌库 | 仅 3–4 人，每人随机独占一个花色 1–13，加一张巫师和一张小丑；每轮重洗个人完整牌库 |

单色第一轮发 4 张，每轮多 1 张，完整局 12 轮至 15 张；快速局 5 轮发 4–8 张。没有主牌，数字牌跨花色比较，最大者胜，同数字先出者较强；巫师、小丑和计分沿用基本规则。单色也可以每轮选择预估变体；先见之明作用于开启当轮的全部手牌。

隐藏手牌、预估和未公开投票在发送玩家状态前过滤，日志和恢复快照也不会提前公开秘密数字。旧的进行中保存状态补充缺少的规则字段并继续当前轮，不重发牌；下一轮开始采用逐轮投票。

## 联机方式与边界

网页和联机入口由 Cloudflare Worker 提供，每个房间通过 Durable Object 的 WebSocket 中继转发消息。房主浏览器仍负责洗牌、验证操作和计分；手机和电脑都可以建房，无需 WebRTC 直连、PeerJS 信令或 TURN 配置。

- 玩家无需游戏账号。所有浏览器主动连接 HTTPS/WSS 网站，中继按连接身份定向转发；房主令牌只在连接握手中传递，服务端保存其 SHA-256 摘要以校验刷新后的房主身份。中继不保存完整牌局、手牌或聊天快照。
- 房主负责保存和推进牌局，没有房主迁移。房主关闭标签页后，其他人无法接管牌局；休眠或长时间切后台也可能暂停联机。
- 普通玩家和房主在同一标签页刷新后，都会自动回到原房间；座位、手牌、预言、轮次、分数和已同步的聊天保存在 sessionStorage。房主刷新时，其他玩家保留当前牌桌并自动重连，无需刷新或重新输入房间码。中继重新建立房主与访客连接可能需要几秒，恢复期间暂停操作，连接成功后继续原来的牌局；不会自动重发尚未确认的操作。
- 单人练习也支持刷新恢复。主动离开、被移出或收到房主关闭房间的通知后，会清除恢复记录。打开不同房间的邀请链接时优先显示该邀请；关闭标签页或清除浏览器会话数据后不保证恢复。
- 联机房间无密码，开局后会公开列出房主昵称、房间码、人数与轮次供其他人观战。程序按当前规则过滤玩家手牌：通常只下发自己的牌，先见之明开启的当轮选色／预估期间则只下发其他玩家的牌；观众始终没有手牌权限，房主掌握全部状态。
- 所有成员需访问同一个新版本网址。旧 PeerJS 房间与中继房间不互通；新域名无法读取旧域名的浏览器会话。在原域名更新版本后，同标签页已有快照可恢复，但房主和访客需一起更新。网络仍需能够访问 Cloudflare HTTPS/WSS。
- 离线练习无需联机服务，但第一次打开网站仍需加载页面资源。

## 本地开发

推荐 Node.js 22 或更新版本。

```sh
npm ci
npm test
npm run build
npm run dev:relay
```

打开 `http://127.0.0.1:8787/` 即可本地建房、加入和观战，运行的是真实 Workers/Durable Objects 本地环境，无需 Cloudflare 账号。需要前端热更新时，在另一终端执行 `npm run dev`，Vite 会把 `/api` 和 WebSocket 代理到 8787。直接使用静态构建时，每次重新 build 后重启 `dev:relay`，避免旧的资源清单。

`src/game.js` 是独立规则引擎；`src/main.js` 保留房主权限、玩家视图和恢复逻辑；`src/room-transport.js`、`src/relay-socket.js` 负责连接和重连；`worker/index.js` 负责中继及目录。构建产物在 `dist/`。

## 发布

```sh
npx wrangler login
npm run deploy
```

`wrangler.jsonc` 配置独立的 `wizard-friends` Worker、静态网页和 SQLite Durable Objects；不修改同账号其他游戏。部署后所有玩家使用 Wrangler 输出的 HTTPS 地址。Cloudflare 授权保存在本机 Wrangler 配置，不能放入前端变量或提交 Git。

如果继续通过 GitHub Pages 提供前端，先部署 Worker，再把仓库 Actions 变量 `RELAY_URL` 设为 Worker 的 HTTPS 根地址，Pages 构建会写入公开的 `VITE_RELAY_URL`。Worker 的 `ALLOWED_ORIGINS` 必须包含前端来源；当前允许原仓库和 fork 的 GitHub Pages 来源。默认的 Worker 同域部署无需此变量。

房间归属摘要和关闭标记在无房主连接 7 天后清理；断开或关闭时撤下目录，失去更新的公开摘要最多保留 90 秒。目录只保存允许公开的房间摘要。服务端重启或休眠后，已认证 WebSocket 使用附件恢复路由身份；房主离线后其他玩家等待原房主，不接管私有状态。

## 规则与素材

按照 [AMIGO 官方 Wizard 规则](https://blog.amigo-spiele.de/content/ap/rule/06900-GB-AmigoRule.pdf) 实现，原游戏设计者 Ken Fisher。本项目为非官方好友同乐实现，与原出版方无关联。牌面使用 CSS、文字和符号独立绘制，不使用盒面、商标图或原版卡图。用户提供的 `reference/` 留在本地，不上传。

注意：巫师和小丑随时可出；首张非小丑若为巫师，本墩不限制花色；若已经由数字牌建立首攻花色，后来出现巫师不会解除跟色。多个巫师先出者胜；全小丑也由先出者胜。猜中得 `20 + 10 × 墩数`，猜错扣 `10 × 偏差绝对值`。

测试包含 3–6 人标准局、3–4 人单色局、三种预估模式、允许的组合、投票重投、特殊牌边界、非法操作、名称冲突和信息隔离；本轮实际验证结果见 `docs/dev-memory/HISTORY.md`。

### 浏览器验证

主页显示“约 N 人在线”：独立 WebSocket 连接到中继目录，统计当前已连接浏览器。同一浏览器多个标签页通过 localStorage 匿名标识去重，机器人不计入。目录最多展示 50 个公开摘要，每房最多 50 名观众；只有已认证房主能发布本房间摘要。

连接中断时显示暂不可用，重连后重新统计；手机后台挂起可能延迟离线检测，因此仍标为“约”。不同设备或浏览器分别计数。每轮投票期间房间暂时退出公开列表，发牌后恢复。

启动本地中继后，可在 PowerShell 中执行 `$env:GAME_URL='http://127.0.0.1:8787/'`，再逐项运行：

```sh
npm run test:browser
npm run test:variants
npm run test:graphics
npm run test:network
npm run test:presence
npm run test:music
npm run test:refresh
npm run test:spectator
```

在线人数浏览器测试验证两个独立浏览器、同浏览器多标签去重、一个浏览器退出后目录保持可用，以及手机布局。人数断言需要独占测试站点，默认使用本地预览。

变体浏览器测试覆盖随机名称、手机投票、先见之明、单色秘密数字快速局、再开局和减少动态效果。联机测试包括分类平票、重投、投票期间刷新恢复、隐藏预估和结果同步。

画质浏览器测试使用实际 WebGL 像素验证「3D 质感 → 省电 → 3D 质感」切换，确保省电立即移除投影、恢复画质后重新产生投影，不残留旧阴影；另以 3 倍 DPR 模拟手机检查 320px／390px、3–6 张牌的投影宽度与边界、装饰牌堆避让及切回桌面的缩放恢复。

需要本机安装 Google Chrome。可通过环境变量 `GAME_URL` 测试部署地址；截图输出至忽略上传的 `.local/`。

`test:refresh`、`test:network`、`test:spectator` 均使用实际 WebSocket 中继，不再替换为 PeerJS 测试连接。联机测试在禁用 WebRTC 的三个独立浏览器会话中运行，房主使用 390px 触控手机视口，验证投票、两轮计分、隐私和刷新恢复。观战测试额外直接发送伪造操作验证房主拒绝权限越界。

`test:presence` 需要独占测试站点，不要与其他联机测试同时运行。浏览器模拟手机视口并不等于真实手机、运营商和锁屏行为的验收。
