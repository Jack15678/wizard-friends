# 巫师牌 · 好友桌

中文 Wizard 好友网页游戏。3–6 人实时房间，邀请链接，机器人练习，自动跟色检查、胜墩判定和计分，逐轮成绩与手机布局。

**在线游玩：[xsk23.github.io/wizard-friends](https://xsk23.github.io/wizard-friends/)**

## 巫师密室 · 3D 视觉版

Three.js / WebGL 实时渲染的木质牌桌、黄铜包边、烛台灯光、魔法阵、书册、水晶球与微粒。桌面卡牌有真实几何厚度、透视、投影、落牌过渡与胜墩高亮；手牌使用 HTML/CSS 的扇形排列和抬牌，保留键盘焦点与合法出牌限制。镜头和手牌角度不随鼠标移动。

主页采用全屏游戏主菜单：烛光牌桌作为背景，左侧仅显示标题、创建牌局、加入房间、单人练习、昵称与在线人数。房间码按需展开，邀请链接自动展开；右下角提供规则和画质入口。没有宣传介绍、参数栏或底部营销说明。

等待大厅延续全屏牌桌场景，六个座位围桌排列；顶部保留房间码、人数、邀请和离开，底部提供机器人、快速局、预言挑战和开始游戏。房主可移除玩家；人数不足或有人离线时显示简短原因并禁用开始。手机改为两列座位。

对局时牌桌铺满浏览器视口，手牌和当前操作浮在桌面下方。轮次与王牌显示在左上角；右上角「计分」展开排行榜、逐轮成绩和牌桌记事，「菜单」提供规则、画质、邀请与退出。终局自动展开成绩，随时可以关闭；Escape 可收起菜单和计分面板。无需滚动整个页面，大量手牌在手牌区内滚动。

六类原创 SVG 雕刻风牌面（冰霜、烈焰、森林、星辰、巫师、小丑）同时用于手牌和三维材质。视觉参考 [Inscryption](https://store.steampowered.com/app/1092790/Inscryption/) 的烛光桌面与 [Liar's Bar](https://store.steampowered.com/app/3097560/Liars_Bar/) 的围桌空间感；未使用这些游戏的模型、贴图、音频或角色素材。

主页右下角或对局右上角的菜单内可切换「3D 质感 / 省电」。手机默认省电，降低像素密度、关闭阴影与微粒；页面隐藏或场景离开页面时停止绘制。尊重系统的减少动态效果偏好。不支持 WebGL 或图形上下文丢失时，自动显示二维牌桌，规则及联机功能保持可用。

`src/table-scene.js` 为三维场景，`src/card-art.js` 为原创牌面，`src/cinematic.css` 为新版视觉覆盖层。三维资源按需加载，模型、木纹和牌面都由代码生成，无外部模型下载。

## 开始玩

1. 打开网站，输入昵称，创建好友房间。
2. 复制邀请链接发给朋友。朋友打开链接、输入昵称，点击加入。
3. 至少三人即可开始；空位可添加机器人，最多六人。
4. 每轮先预言赢墩数，再依次出牌。亮起的手牌表示当前合法选择。
5. 房主在每墩和每轮结算后点击继续。终局可再次开局。

标准局包含 20/15/12/10 轮（分别对应 3/4/5/6 人）。可选 5 轮快速局、预言总和不等于本轮墩数的规则变体。机器人仅为简单陪练策略。

## 联机方式与边界

这是 GitHub Pages 静态网站，通过 PeerJS / WebRTC 在玩家浏览器之间传递消息，房主浏览器负责洗牌、验证操作和计分。

- 无需游戏账号或数据库。公网 PeerJS Cloud 负责建立连接，实际游戏数据通过 WebRTC 传输。
- 房主必须保持页面打开，不能关闭、休眠或长时间切后台。无房主迁移；房主关闭标签页后对局无法恢复。
- 普通玩家在同一标签页刷新后，重新加入原房间可以恢复座位；身份存在 sessionStorage。房主同标签页刷新会尝试恢复保存状态，服务释放旧连接可能需要稍等。
- 房间只有八位邀请码保护，无密码；仅与信任的好友分享。程序不向普通玩家下发其他玩家手牌，但房主掌握全部状态。
- 严格 NAT、企业防火墙或无法访问 PeerJS 的网络可能不能直连。默认没有 TURN 中继。连接失败可换网络，或者通过 `.env.example` 配置自己的 TURN。浏览器构建中的 `VITE_*` 都是公开数据，正式 TURN 应使用有时效及限额的凭据。
- 离线练习无需联机服务，但第一次打开网站仍需加载页面资源。

## 本地开发

推荐 Node.js 22；也兼容本机 Node.js 20.13。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`src/game.js` 是独立规则引擎；`src/main.js` 包含 UI、房间同步和重连；`src/style.css` 为响应式界面。构建产物在 `dist/`，相对资源路径兼容 GitHub Pages 项目子路径。

## 发布

仓库内 `.github/workflows/pages.yml` 在推送 main 时执行测试、构建及 GitHub Pages 部署。仓库 Settings → Pages → Source 使用 **GitHub Actions**。

## 规则与素材

按照 [AMIGO 官方 Wizard 规则](https://blog.amigo-spiele.de/content/ap/rule/06900-GB-AmigoRule.pdf) 实现，原游戏设计者 Ken Fisher。本项目为非官方好友同乐实现，与原出版方无关联。牌面使用 CSS、文字和符号独立绘制，不使用盒面、商标图或原版卡图。用户提供的 `reference/` 留在本地，不上传。

注意：巫师和小丑随时可出；首张非小丑若为巫师，本墩不限制花色；若已经由数字牌建立首攻花色，后来出现巫师不会解除跟色。多个巫师先出者胜；全小丑也由先出者胜。猜中得 `20 + 10 × 墩数`，猜错扣 `10 × 偏差绝对值`。

测试包含 3–6 人标准局完整推进、两种预言模式、特殊牌边界、非法操作和手牌隔离；浏览器和公网联机验证结果以项目交付说明为准。

### 浏览器验证

主页显示“约 N 人在线”：使用独立 PeerJS 连接自动选举统计节点，统计同一站点当前已连接的浏览器，包括主页、房间和对局中的玩家；同一浏览器的多个标签页通过本地匿名标识合并。机器人不计入。匿名标识保存在 localStorage，不传输昵称、房间码或牌局内容。

这是好友小群体使用的点对点估算，并非服务器权威统计：网络/NAT 限制、后台冻结可能少计，心跳过期约 90 秒移除；统计节点关闭后自动重新选举，恢复期间显示暂不可用。网络错误不会显示虚构人数。多个设备或不同浏览器仍分别计数；清除浏览器数据会生成新标识。

已在本机 Chrome 验证 5 轮完整练习局、390px 手机布局，以及三个独立浏览器会话通过公网 PeerJS 信令完成加入、出牌、计分同步和访客刷新恢复。此测试不代表所有异地 NAT / 防火墙组合均可连接。

启动 `npm run dev` 后，可在另一终端运行：

```sh
npm run test:browser
npm run test:network
npm run test:presence
```

在线人数浏览器测试验证两个独立浏览器、同浏览器多标签去重、统计节点关闭后的重新选举，以及手机布局。人数断言需要独占测试站点，默认使用本地预览。

需要本机安装 Google Chrome。可通过环境变量 `GAME_URL` 测试部署地址；截图输出至忽略上传的 `.local/`。
